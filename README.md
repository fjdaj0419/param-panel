# Param Panel · 参数调节面板

> 当 AI 要问"你想要多强 / 几成 / 什么风格"时，别让它打一行字问你——让它弹一个面板，**参数一动，右边产品立刻跟着变**，你自己挑出最舒服的那个，再让它继续干活。

一个 Agent Skill（适用于 WorkBuddy、Claude Code 等支持 `SKILL.md` 的环境）。

---

## 它解决什么问题

让 AI 做海报、落地页、界面、图表时，总有些参数得你来定：圆角多大、配色多鲜艳、要不要徽章、价格区间怎么划。

传统做法是 AI 反问你一句"你想要什么风格？"，然后你**凭空猜一个词**，它做出来，你不满意，再改。来回三五轮，而且你根本不知道那个词对应什么样子。

这个技能把"文字反问"换成**带真实产品预览的调节面板**：

- 左边是控件，右边是产品的实时缩略图
- 你点一下"珊瑚色"，右边卡片当场转暖
- 你把圆角拉大，卡片和按钮一起变圆
- 你打开"限时徽章"，徽章立刻出现在卡片上
- 挑到顺眼，点确认，值自动回到对话，AI 接着往下做

**你不是在猜数字，你是在挑成品。**

---

## 四种控件

| 类型 | 用于 | 长相 |
|---|---|---|
| 分段档位 `segment` | 有限选项：低/中/高、冷静/活力/热烈 | 一排按钮，选中高亮 |
| 档位滑块 `slider` | 范围内的若干刻度：强度、透明度、百分比、尺寸 | 轨道 + 圆点 + 实时数值 |
| 开关 `switch` | 开/关：要不要徽章、要不要阴影 | 拨动开关 |
| 双端区间 `range` | 一段范围：价格区间、日期区间 | 下限、上限两条轨道 + 高亮段 |

可同屏放 **2–5 个**参数，互不干扰，任一变动预览即时重绘。

## 安装

### WorkBuddy

```
设置 → 技能 → 添加技能 → 上传技能 → 选择 param-panel.skill
```

或者直接把本仓库克隆到技能目录：

```bash
git clone https://github.com/fjdaj0419/param-panel.git ~/.workbuddy/skills/param-panel
```

### Claude Code / 其他支持 Agent Skills 的环境

```bash
git clone https://github.com/fjdaj0419/param-panel.git ~/.claude/skills/param-panel
```

本仓库是标准 Agent Skill 结构：根目录 `SKILL.md`（YAML frontmatter 只含 `name` 和 `description`）+ `assets/`，没有绑定任何平台的私有字段，所以换环境照样能用。

### 手动

把 `SKILL.md` 和 `assets/` 放进任意 `skills/param-panel/` 目录即可。

## 使用

### 自动触发

装上就生效，正常说话就行：

- "帮我做个落地页，动效强度你来定"
- "海报配色给几个方案我自己挑"
- "价格区间你看着定"

命中这几类语义时它自己会弹面板：**程度、百分比、比例、多强、多大、档位、强度、配色、风格、调一下、你来定、调到合适、最佳效果、看看效果**。

### 手动点名

在输入框打 `/`，从列表里选 `param-panel`，再写需求：

```
/param-panel 帮我做活动页，配色和圆角我来调
```

### 它不会乱弹

必须同时满足四条才触发：正在生成产品 / 缺一个可调参数 / 你没给明确数值 / **能做出可视化预览**。

最后一条是硬门槛：如果只能给你一句文字描述、产品看不出变化，它宁可直接文字问你，也不弹一个没用的面板。

## 技术实现（这段是本项目的核心）

面板是**纯静态 HTML + CSS**，交互靠 CSS `:has()` 改 CSS 变量，**没有任何脚本参与渲染**。

```css
.pp:has(#tone-night:checked){--card-bg:#1C1C1E; --accent:#FF9F0A}
.pcard{background:var(--card-bg); border-radius:var(--r)}
```

选中的单选按钮 → `.pp` 拿到新变量 → 卡片读变量自动重绘。浏览器原生能力，零 JS。

为什么这么设计？因为踩过坑：

1. **宿主把 HTML 注入页面时，`<script>` 不会执行**（`innerHTML` 注入的脚本按浏览器规范本就不运行）。早期版本用 `document.createElement` 现场拼 DOM，结果整块面板空白——用户只看到一个空框。
2. **渲染器禁止 `<form>`**，会直接报错拒绝加载。
3. 需要 JS 的地方只有两个按钮（重置、确认），写成内联 `onclick`，符合渲染器"用事件处理器"的要求。

结果是**降级安全**：就算 `onclick` 也不执行，面板依然完整可见、可点、会联动，你只是需要口头回一句"就按这个做"。

## 自定义

改模板只需动三处：

| 改什么 | 怎么改 |
|---|---|
| 文案 | 标题 `.hd`、副标题 `.sub`、参数标签、选项文字、卡片文案 |
| 配色 | `:has(#tone-*:checked)` 那几行里的色值 |
| 卡片内容 | 可以自由改 `.pcard` 内部结构，但保留 `pcard` `badge` `kick` `ttl` `dsc` `chips` `chip` `barw` `bar` `foot` `plab` `btn` 这些 class——联动全靠它们 |

加/减档位时记得在 `</style>` 前补上对应的 `.pp:has(#你的id:checked){--变量:值}`，漏了那一行该档位就没有视觉反馈。

## 已知限制

- 滑块是**分级刻度**（点击轨道定位），不是连续拖拽——这是为了换取零脚本依赖，刻度建议不超过 6 档。
- 双端区间的上下限不会互相约束，可以拉成空区间（视觉上高亮段消失）。
- 预览卡片是通用商品/活动卡片形态。要换成完全不同的产品（如手机界面、图表），改 `.pcard` 内部结构即可，class 保留。
